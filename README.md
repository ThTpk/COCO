# 2Dto3D

สร้างโมเดล 3D ที่พร้อมใส่โครงกระดูก จากภาพตัวละคร 2D หลายมุม (หน้า / หลัง / ข้าง)
ปลายทางคือไฟล์ `.glb` ที่เปิดใน three.js, Unity, Unreal หรือ Blender ได้ทันที

## ติดตั้ง

ดู [SETUP.md](SETUP.md) สำหรับ toolchain (CUDA, VS Build Tools) จากนั้น:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe tools\check_env.py
```

## ใช้งาน

วางภาพลงใน `input/` โดยตั้งชื่อให้มีคำว่า `front`, `back`, `side`:

```
input/
  Front.jpeg     # บังคับ
  Back.jpeg      # บังคับ
  Left.jpeg      # บังคับ — มุมข้าง (ชื่อ side / left ก็ได้)
  Right.jpeg     # ไม่บังคับ — มุมข้างอีกฝั่ง ช่วยให้ความหนาลำตัวแม่นขึ้น
  down.jpeg      # ไม่บังคับ — มองจากใต้ฝ่าเท้า ใช้เป็น "ผังฝ่าเท้า"
```

มุมข้างสองใบจะถูกพลิกอัตโนมัติให้หน้าชี้ไปทางเดียวกัน โดยดูจากภาพเอง
(หัวกับปลายเท้าชี้ไปทางไหน) ไม่ได้เชื่อชื่อไฟล์ — คนตั้งชื่อ `left` กันคนละ
ความหมายอยู่เสมอ (ข้างซ้ายของตัวละคร กับ กล้องอยู่ทางซ้าย)

`down.jpeg` **ไม่เข้า visual hull** เพราะเป็นภาพ perspective แรง ใช้เฉพาะ
เป็นรูปร่างฝ่าเท้าในระนาบ X-Z ซึ่งเป็นระนาบเดียวที่มุมหน้า/หลัง/ข้าง
มองไม่เห็นเลย — ดูหัวข้อ [มือกับเท้า](#มือกับเท้า)

แล้วรัน:

```powershell
.venv\Scripts\python.exe -m src.cli --rig none --height 2.1
```

## สร้างจากคลิปกล้องวนรอบตัว (โมเดลที่ 2)

ถ้ามีคลิปที่กล้องวนรอบตัวละครจนครบรอบ ใช้คลิปนั้นแทนภาพนิ่งสี่ใบได้เลย

```powershell
.venv\Scripts\python.exe -m src.clipcli --video input\clip.mp4 --name character2 --height 2.1 --rig blender
```

ได้ `output/character2.glb`, `character2_rigged.glb`, `character2_texture.png`
และ `character2_joints.json` เหมือนเส้นทางภาพนิ่งทุกอย่าง

### ทำไมไม่ใช่แค่ "หยิบ 4 เฟรมมาใช้"

คลิปไม่ได้บอกอะไรมาเลยนอกจากภาพ สิ่งที่ต้องหาเองก่อนจะเฉือน voxel ได้คือ

1. **เฟรมไหนกล้องอยู่มุมไหน** — และกล้องจริงไม่ได้วนด้วยความเร็วคงที่
   คลิปตัวอย่างวน 1.0 องศา/เฟรมช่วงต้น แล้วเร่งเป็น 3.1 องศา/เฟรมช่วงกลาง
   ถ้าเดาว่าคงที่ มุมของเฟรมกลางคลิปจะเพี้ยนไปกว่า 40 องศา — "มุมข้าง"
   ที่เลือกได้จะกลายเป็นมุมเฉียง แล้ว hull พังทั้งใบ
2. **กล้องห่างแค่ไหนในแต่ละเฟรม** — กล้องเดินเข้าออกตลอดคลิป ตัวละครจึงโตขึ้น
   เกือบสองเท่าระหว่างเฟรมแรกกับเฟรมกลาง
3. **ระดับพื้นอยู่แถวไหนของภาพ** — ช่วงที่กล้องเข้าใกล้ที่สุด เท้าหลุดขอบล่าง
   ไปแล้ว จึงวัดจาก mask ตรง ๆ ไม่ได้

`turntable.py` หาสามอย่างนี้จากคลิปเอง: ต่อโซ่มาตราส่วนด้วย SIFT ระหว่างเฟรม
ติดกัน ตรึงด้วยเฟรมที่เห็นหัวหรือเห็นเท้า หาคาบการวนจากเฟรมที่เงาซ้ำกับเฟรมต้น
และหามุมหน้าจากความสมมาตรซ้ายขวาบวกทิศที่ตัวละครหันหน้าในมุมข้าง

ส่วนจังหวะการวนที่ไม่คงที่ `clipcarve.fit_angles` ดัดให้เอง โดยเลื่อนจุดควบคุม
ทุก ๆ 45 องศาแล้ววัดว่า "เงาที่ฉายกลับจาก hull ทับ mask จริงได้ดีขึ้นไหม"
(IoU เฉลี่ยของคลิปตัวอย่างขึ้นจาก 0.75 เป็น 0.82) — ไม่ต้องมีเฉลยจากที่ไหน

### ปัญหาที่คลิปมีแต่ภาพนิ่งไม่มี

| ปัญหา | ทางแก้ในโค้ด |
|---|---|
| ช่วงกลางคลิปกล้องเข้าใกล้จนขาหลุดเฟรม | voxel ที่ฉายออกนอกเฟรม = *ไม่รู้* ไม่ใช่ *ไม่มีเนื้อ* มุมนั้นจึงไม่ได้ออกเสียงเฉือนขาทิ้ง |
| ตัวละครในคลิป AI ไม่คงรูป (เฟรมมุมเดียวกันห่างกันหนึ่งรอบ IoU แค่ 0.68) | ไม่ใช้ min ของทุกมุมตามตำรา แต่ใช้ค่าน้อยอันดับที่ `--drop`+1 จึงยอมให้มุมเพี้ยนได้ไม่กี่มุม |
| ใต้เข่าลงไปเหลือมุมเห็นไม่กี่มุม | จำนวนมุมที่ยอมให้ค้านได้คิดตามจำนวนมุมที่เห็นจริง (`--tol-views`) ไม่งั้นปลายนิ้วเท้าจะยืดเป็นลิ่มแบนไปข้างหน้า เพราะไม่มีมุมไหนเหลือมาบอกว่าเท้ายาวแค่ไหน |
| เงาบนพื้นกับขอบล่างของเฟรมทิ้งแผ่นแบนปูพื้นไว้ | `--open` ลบแผ่นที่บางกว่าที่กำหนด แขนขาหนาหลายสิบ voxel จึงรอด |

### สองโหมด

| โหมด | ทำอะไร | เหมาะกับ |
|---|---|---|
| `--mode hull` (ค่าเริ่มต้น) | เฉือน voxel จาก 24 มุมพร้อมกันด้วยสนามระยะ หน้าตัดจึงเป็นรูปจริงของตัวละคร ไม่ใช่วงรีที่เดาจากสองแกน | คลิปที่วนครบรอบ |
| `--mode views` | ประกอบภาพสี่มุมหลักจากคลิป (เติมส่วนที่หลุดเฟรมจากเฟรมมุมใกล้เคียง และจากภาพสะท้อนของมุมตรงข้าม) แล้วส่งเข้า `src.cli` ตามเดิม | เมื่ออยากได้ของที่มีแต่เส้นทางภาพนิ่ง เช่น การเซาะคอ การลากหาง ผังฝ่าเท้า |

โหมด `views` เขียนภาพสี่มุมไว้ที่ `output/clip_views/` เปิดดูได้ และภาพตรวจงาน
`output/debug/05_clip_views.png` ย้อมสีชมพูตรงส่วนที่ "ยืม" มาจากเฟรมอื่น
จะได้รู้ว่าส่วนไหนของผลลัพธ์มาจากข้อมูลจริง

### texture: เลือกมุมที่ดีที่สุด ไม่ใช่เฉลี่ยทุกมุม

ขั้นฉายสีของเส้นทางภาพนิ่งเฉลี่ยสี่มุมเข้าด้วยกัน ซึ่งใช้ได้เพราะภาพทั้งสี่
เป็นภาพเดียวกันของตัวละครตัวเดียวกัน แต่กับคลิป การเฉลี่ยสี่สิบเฟรมคือการ
ทำลายลาย: ตัวละครในคลิปไม่คงรูป จุดเดียวกันบนผิวจึงไปตกคนละที่บนลายของ
แต่ละเฟรม เกล็ด โซ่ เข็มขัด ถูกเกลี่ยจนเหลือแต่ก้อนสี

`cliptexture.py` จึงเก็บแค่ **สองมุมที่เห็นจุดนั้นดีที่สุด** แล้วผสมมุมที่สอง
เข้ามาเฉพาะตอนที่มันดีพอ ๆ กับมุมแรก (`--texture-blend` ยิ่งมากยิ่งคม) —
มุมเดียวที่คมอยู่แล้วย่อมให้ลายคมกว่าค่าเฉลี่ยเสมอ ส่วนที่ยังเก็บมุมที่สอง
ไว้ ก็เพื่อไม่ให้เกิดรอยต่อคมตรงที่สองมุมดีเท่ากัน

คะแนนของแต่ละมุมคิดจากสี่อย่างที่เป็นอิสระต่อกัน

| สัญญาณ | ทำไมต้องมี |
|---|---|
| ผิวหันเข้าหากล้องแค่ไหน | ผิวที่เฉียงมากถูกบีบจนลายยืด |
| เฟรมนี้เห็นตัวละครใหญ่แค่ไหน | เฟรมระยะใกล้ให้รายละเอียดมากกว่าเฟรมที่กล้องถอยออกไปเกือบเท่าตัว |
| จุดนั้นอยู่ลึกเข้าไปในเงาแค่ไหน | ริมขอบ silhouette คือที่ที่ geometry กับ mask เหลื่อมกันเสมอ สีตรงนั้นมักเป็นพื้นหลังที่ถูกดูดเข้ามา |
| **ถูกบังหรือเปล่า** | ดูย่อหน้าถัดไป |

การถ่วงน้ำหนักด้วย normal บอกได้แค่ว่าผิวหันไปทางไหน ไม่ได้บอกว่ามีอะไรขวาง
ผิวอกที่หันเข้ากล้องแต่มีแขนบังอยู่จะดูดสีแขนมาแปะ กลายเป็นเงาแขนลอยอยู่บนอก
จึงต้องมี depth buffer หยาบ ๆ ต่อมุม (ยิงจุดบนผิวลงไปแทนการ rasterize
สามเหลี่ยม เพราะ texel หนาแน่นกว่าพิกเซลของ buffer อยู่แล้ว) — ในคลิปตัวอย่าง
ตัดการมองที่ถูกบังออกไป 9 ล้านครั้ง

สุดท้ายปรับความสว่างของแต่ละเฟรมให้เท่ากันก่อนใช้ เพราะคบไฟกับหมอกในฉากทำให้
แต่ละเฟรมสว่างไม่เท่ากัน พอ texel คนละหย่อมเลือกคนละเฟรม ความต่างนั้นจะโผล่
เป็นรอยปะบนผิว

ผลที่วัดได้: ความคมของ texture (ความแปรปรวนของ Laplacian) ขึ้นจาก 159 เป็น 261
ซึ่งคมกว่าโมเดลที่สร้างจากภาพนิ่งสี่ใบ (238) ด้วยซ้ำ

### ตัวเลือกที่ใช้บ่อย

| ตัวเลือก | ทำอะไร |
|---|---|
| `--reuse` | ใช้ผลประเมินกล้องที่เก็บไว้ใน `output/clip_cache/solution.json` — ข้ามขั้นที่ช้าที่สุด (ราว 4 นาที) |
| `--views 24` | จำนวนมุมที่เอามาเฉือน มากไปก็ไม่ดี เพราะยิ่งหลายมุมยิ่งเจอความไม่คงรูปของคลิปมากขึ้น |
| `--drop 2` | ยอมให้กี่มุมค้านได้ ลดลงถ้าตัวอ้วนเกิน เพิ่มถ้าแขนขาหาย |
| `--voxel-res 320` | ความละเอียดกริด |
| `--texture-blend 6` | ยิ่งมากยิ่งคม — 0 คือเฉลี่ยสองมุมที่ดีที่สุดเท่า ๆ กัน |
| `--texture-views 48` | จำนวนเฟรมที่ให้เลือกตอนฉายสี มากขึ้น = มีโอกาสเจอมุมที่คมกว่า แต่ bake นานขึ้น |
| `--refine 2` | ดัดมาตราส่วนรายเฟรมให้เข้ากับ hull — IoU ดีขึ้นจริง แต่ตัวจะอ้วนขึ้นด้วย ค่าเริ่มต้นจึงเป็น 0 |

### ข้อจำกัดของคลิปตัวอย่าง

ไม่ใช่ข้อจำกัดของโค้ด แต่เป็นของคลิปเอง — รู้ไว้ก่อนจะได้ไม่เสียเวลาปรับผิดจุด

* ตัวละครในคลิป **ไม่ได้อยู่ท่า A-pose** แขนแนบลำตัว ช่องว่างระหว่างแขนกับ
  ลำตัวกว้างแค่ 10-20 พิกเซล รูปทรงที่ได้ตรงหัวไหล่จึงตันกว่าโมเดลจากภาพนิ่ง
* **ไม่มีคอให้เห็นในมุมไหนเลย** หัวตั้งบนบ่าที่ใหญ่กว่ากะโหลก (ดูหัวข้อ
  [หัวกับคอ](#หัวกับคอ))
* **ไม่มีเฟรมไหนเห็นขาจากด้านหลัง** กล้องเข้าใกล้ที่สุดพอดีตอนวนไปด้านหลัง
  ด้านหลังของขาจึงเป็นส่วนที่ hull เดาเองล้วน ๆ
* ตัวละคร**เปลี่ยนสัดส่วนระหว่างคลิป** ตัวกว้างขึ้นราว 12% ระหว่างต้นคลิป
  กับท้ายคลิป ซึ่งเป็นอาการปกติของคลิปที่ AI สร้าง

## ขนาดไฟล์

| ไฟล์ | ก่อน | หลัง |
|---|---|---|
| `character_rigged.glb` | 5.49 MB | **1.21 MB** |
| `character.glb` | 5.16 MB | **2.07 MB** |
| `character_texture.png` | 4.80 MB | 4.80 MB (ไม่แตะ) |

บีบสองชั้น ตามสัดส่วนที่วัดได้จริง

**texture กิน 70-80% ของไฟล์** จึงบีบก่อน เก็บเป็น PNG (ไม่สูญเสีย) แพงมาก
สำหรับภาพที่มีไล่เฉดเต็มไปหมด เปลี่ยนเป็น JPEG q88 แบบไม่ลด chroma
(`subsampling=0`) เหลือ 0.88 MB โดยซูมดูเกล็ดแล้วยังคมเท่าเดิม
glTF รองรับ `image/jpeg` มาแต่ต้น ไม่ต้องใช้ส่วนขยายใด ๆ จึงเปิดได้ทุกที่
ต่างจาก KTX2 หรือ WebP ที่ต้องมีตัวรองรับเพิ่ม

**geometry เหลือเป็นส่วนใหญ่หลังจากนั้น** จึงบีบด้วย Draco ต่อ ได้อีกเท่าตัว
ตัวนี้ผู้อ่านต้องมี decoder — Blender, three.js, Babylon, Unity glTFast, Godot
รองรับหมด แต่เครื่องมือเก่าบางตัวไม่รองรับ ปิดด้วย `--no-draco` ถ้าต้องการ
ไฟล์ที่เปิดได้ทุกที่

`character.glb` ไม่ได้ผ่าน Draco เพราะ trimesh เป็นตัวเขียน (ไม่รองรับ) และ
ไฟล์นี้มีไว้ส่งต่อไป Mixamo ซึ่งไม่อ่าน Draco อยู่แล้ว

`character_texture.png` ยังเป็นความละเอียดเต็มเสมอ ไม่มีอะไรโหลดมัน
มันมีไว้ให้เอาไป retouch ต่อ

```powershell
--texture-quality 95     # คมขึ้น ไฟล์ใหญ่ขึ้น
--texture-quality 0      # เก็บเป็น PNG ไม่บีบเลย
--texture-glb-size 1024  # ย่อ texture ใน GLB (ไฟล์ PNG ข้าง ๆ ยังเต็ม)
--no-draco               # ไม่บีบ geometry
```

ถ้ายังใหญ่ไป `--texture-glb-size 1024` ลดส่วน texture ลงอีกสี่เท่า
และ `--target-tris 20000` ลดส่วน geometry ลงครึ่งหนึ่ง

## หน้าเดินเล่น (`web/`)

กด WASD หรือปุ่มลูกศรเพื่อเดิน กด Shift ค้างเพื่อวิ่ง ลากเมาส์หมุนกล้อง
สกรอลล์เพื่อซูม บนจอสัมผัสจะมีปุ่มทิศทางขึ้นมาให้เอง

**ความเร็วเดินผูกกับจังหวะก้าวของ clip** — `Walk` ยาว 32 เฟรม @ 24fps
= 1.33 วินาทีต่อหนึ่งรอบ (สองก้าว) ตัวละครสูง 2.1 ม. ก้าวละราว 0.9 ม.
จึงได้ `WALK_SPEED = 1.35` ม./วินาที ถ้าตั้งผิดจากนี้มากเท้าจะไถลกับพื้น
เพราะ clip ไม่มี root motion ตอนวิ่งก็คูณทั้งความเร็วและ `timeScale`
ด้วยค่าเดียวกัน อัตราส่วนจึงคงเดิม

clip ถูกเลือกจาก **ความเร็วจริง** ไม่ใช่จากปุ่มที่กด ตอนปล่อยปุ่มแล้วตัวละคร
ยังไถลอยู่จึงยังเดินต่อจนหยุดสนิท ไม่ใช่หยุดขยับขาทันทีทั้งที่ยังเคลื่อนที่

**เรื่องทิศทาง** ทิศเดินคิดจากเวกเตอร์ของกล้องตรง ๆ ไม่ใช่หมุนเวกเตอร์อินพุต
ตามมุมกล้อง — ทิศ "ออกห่างจากกล้อง" คือ `(sin, cos)` ส่วนทิศขวาของจอคือ
`forward × up` ซึ่งได้ `(-cos, sin)` ไม่ใช่ `(cos, -sin)` ที่ได้จากการหมุน
เวกเตอร์ `(1,0,0)` ถ้าเดาเครื่องหมายเอาจะกลับด้านทั้งสองแกน

## ถ้าผิวเป็นลอนถี่หรือเป็นวงแหวน

**เช็คก่อนเลย: `.glb` มี attribute `NORMAL` หรือเปล่า**

```powershell
.venv\Scripts\python.exe -c "from pygltflib import GLTF2; print(GLTF2().load('output/character.glb').meshes[0].primitives[0].attributes)"
```

ถ้าไม่มี `NORMAL` ตัวโหลด (three.js, Blender, engine ทั่วไป) จะคิด normal ใหม่
แบบ flat ต่อสามเหลี่ยม ผิวที่เรียบสนิทจะกลายเป็นเหลี่ยมทันที และเพราะขั้น
decimate สร้างสามเหลี่ยมยาวตามแนวนอน (ผิวถูกปั้นทีละแถวความสูง) แต่ละแถบจะ
อ่านออกมาเป็นสันวงแหวนรอบตัว **ทั้งที่เรขาคณิตไม่มีสันอยู่จริงเลย**

นี่คือกับดักที่เสียเวลาหาสาเหตุนานที่สุดในโปรเจกต์นี้ ก่อนจะไปปรับพารามิเตอร์
ของขั้น carve ให้ตัดภาคตัดขวางของกริดออกมาดูก่อนเสมอว่าลอนมีอยู่จริงไหม

ถ้ามี `NORMAL` แล้วยังเป็นลอน ค่อยไล่สามอย่างนี้ — ทั้งหมดเกิดจากการที่เรา
ปั้นหน้าตัดทีละแถวอย่างอิสระ

| อาการ | สาเหตุ | แก้ด้วย |
|---|---|---|
| ลอนถี่ ๆ ทั่วตัว | ขอบ silhouette สั่น 1–2 px ระหว่างแถว | `--silhouette-smooth` |
| สันวงแหวนรอบคอ/หัว | หนามหรือเขาในมุมข้าง ยืดความลึกของหน้าตัดทั้งวง | `--spike-open`, `--depth-median` |
| ขั้นกระโดดเป็นช่วง ๆ | จำนวนท่อนใน silhouette เปลี่ยน (แขนแยก/ติดลำตัว) | `--profile-smooth` |

เหตุผลร่วมคือเรามีแค่ภาพหน้ากับข้าง **ไม่มีภาพมุมบน** จึงไม่มีทางรู้ว่าส่วนที่
ยื่นออกมาอยู่ตรงไหนรอบตัว หนามอันเดียวบนสันหลังจึงถูกตีความเป็นความลึกของ
หน้าตัดทั้งวง ถ้า generate ภาพมุมบนเพิ่มได้ ปัญหากลุ่มนี้จะหายไปเกือบหมด

## UV texture

ค่าเริ่มต้นคือ `--texture-mode uv` ซึ่งคลี่ผิวออกเป็นแผ่นแบนแล้ว bake สีลงภาพ
2048×2048 แทนการเก็บสีไว้ที่ vertex

| | vertex color | UV texture 2048² |
|---|---|---|
| จำนวนจุดสี | 20,002 | 4,194,304 |
| ความละเอียดบนผิว | ~12 มม. | ~0.9 มม. |
| เพิ่มรายละเอียดด้วย | เพิ่ม polygon | เพิ่มขนาดภาพ |

บรรทัดล่างสุดคือเหตุผลที่เกมใช้ texture — เพิ่มความคมโดยไม่เพิ่ม polygon
ต้นทุนตอน render แทบไม่เปลี่ยน เปลืองแค่หน่วยความจำ texture

```
คลี่ผิว (xatlas)  ->  rasterize สามเหลี่ยมเป็น texel  ->  ฉายสีจาก 3 มุม  ->  ขยายขอบ island
```

ขั้นฉายสีใช้ `texture.project_colors()` ตัวเดียวกับโหมด vertex ต่างกันแค่ว่า
จุดที่ส่งเข้าไปคือ texel ไม่ใช่ vertex ตรรกะเลือกมุมและถ่วงน้ำหนักเหมือนกันทุกอย่าง

**การขยายขอบ island (`uv_padding`)** ไม่ใช่ของตกแต่ง ตอน render GPU กรองสีแบบ
bilinear และใช้ mipmap ซึ่งทั้งสองอย่างดูดสีจาก texel ข้างเคียง ถ้านอกขอบ island
เป็นสีดำ จะเห็นเป็นเส้นดำบาง ๆ ตามรอยผ่าทั่วตัว ยิ่งมองไกลยิ่งชัดเพราะ mipmap
เฉลี่ยกว้างขึ้น

```powershell
--texture-mode vertex   # กลับไปเก็บสีที่ vertex
--texture-size 4096     # ละเอียดขึ้นอีกเท่าตัว
```

### กับดักสองอันที่ทำให้ texture ดูพัง

**glTF ตั้ง `metallicFactor = 1.0` เป็นค่าเริ่มต้น** แปลว่า "ผิวโลหะเต็มร้อย"
ซึ่งสะท้อนภาพสิ่งแวดล้อมเป็นหลัก ฉากที่ไม่มี environment map จึงเรนเดอร์
ออกมาเกือบดำสนิท ทั้งที่ texture ถูกต้องทุกอย่าง ต้องกำหนด PBRMaterial เอง

**trimesh พลิกแกน V ตอนเขียน glTF** (`v -> 1-v` ส่วน U คงเดิม) เพราะมันเก็บ UV
ตามแบบ OpenGL ที่จุดกำเนิดอยู่มุมซ้าย*ล่าง* ส่วน glTF อยู่ซ้าย*บน*
อาการเวลาลืมไม่ใช่ภาพกลับหัวทั้งใบอย่างที่คาด แต่เป็น **texture แมปผิดที่เป็น
หย่อม ๆ** (หน้าอกกลายเป็นผ้ายีนส์) เพราะแต่ละ island ไปตกบนบริเวณอื่นของ atlas
คนละที่กัน `export.py` พลิกภาพกลับมาชดเชยให้แล้ว

## อนิเมชัน

`--rig blender` ใส่ clip มาให้ในไฟล์เดียวกันเลย

| clip | ความยาว | ทำอะไร |
|---|---|---|
| `Idle` | 64 เฟรม | ยืนหายใจ หางแกว่งเบา ๆ |
| `Walk` | 32 เฟรม | เดินครบรอบ แขนแกว่งสวนขา ลำตัวบิดสวนสะโพก |
| `TailSwing` | 40 เฟรม | สะบัดหางอย่างเดียว ใช้ตรวจว่ากระดูกหางผูกกับเนื้อถูกไหม |

ท่าทางนิยามไว้ใน [src/animation.py](src/animation.py) เป็น **ข้อมูลล้วน** ไม่ใช่โค้ด
แต่ละ channel คือคลื่นไซน์หนึ่งลูกบนกระดูกหนึ่งชิ้น

```
มุม(t) = offset + amp * wave(2π * (harmonic * t + phase))
```

`t` วิ่ง 0..1 ตลอดหนึ่งลูป ทุก clip จึงวนต่อเนื่องได้เองโดยไม่ต้องจัดการรอยต่อ
แก้ท่าได้โดยแก้ตัวเลขในไฟล์นั้น ไม่ต้องแตะโค้ดฝั่ง Blender เลย

`mode` มีสามแบบ: `sin` แกว่งสองทาง, `halfsin` เอาเฉพาะครึ่งบวก (เข่างอได้ทางเดียว),
`const` ค่าคงที่ ส่วน `tail_wave()` สร้างคลื่นวิ่งไล่จากโคนหางไปปลายหาง โดยให้
แต่ละข้อเริ่มขยับช้ากว่าข้อก่อนหน้า หางจึงสะบัดเป็นคลื่น ไม่ใช่แกว่งทั้งท่อน
เหมือนไม้แข็ง

**เรื่องแกนหมุน** ท่าเขียนง่ายที่สุดเมื่อคิดเป็นแกนโลก ("ยกต้นขาไปข้างหน้า"
= หมุนรอบ X) แต่ Blender เก็บท่าของกระดูกเป็นค่าสัมพัทธ์ในระบบแกนของกระดูกเอง
ซึ่งเอียงไปตามทิศที่กระดูกชี้ `_world_rot_to_basis()` ทำการย้ายฐานด้วยสูตร
`M⁻¹ R M` ให้ หลัง importer แปลงแล้วตัวละครหันหน้าไปทาง **-Y** ใน Blender

```
หมุนรอบ X = แกว่งหน้า-หลัง   (ค่าบวก = ไปข้างหลัง)
หมุนรอบ Y = เอียงซ้าย-ขวา
หมุนรอบ Z = บิดลำตัว / สะบัดหาง
```

ปิดด้วย `--no-anim` ถ้าต้องการแค่ rig เปล่า ๆ ปรับเฟรมเรตด้วย `--fps`

### กับดักฝั่ง Blender ที่เจอ

**Blender คืน exit code 0 แม้สคริปต์ traceback กลางคัน** ตัวเรียกจึงนึกว่าสำเร็จ
แล้วหยิบไฟล์เก่าจากการรันครั้งก่อนมาใช้ ตอนนี้ `rigging.py` บังคับให้สคริปต์
ประกาศ `เสร็จสมบูรณ์` ออกมาด้วย ถ้าไม่มีสัญญาณนั้นถือว่าล้มเหลว

**`action.fcurves` หายไปใน Blender 4.4+** เพราะเปลี่ยนไปใช้ action แบบ
layer/strip/slot แล้ว fcurve ย้ายไปอยู่ใน channelbag `_action_fcurves()`
รองรับทั้งสองแบบ และการ keyframe ต้องผูก `action_slot` ให้ก่อนด้วย

## หาง — ลากจากภาพด้านหลังภาพเดียว

ภาพแต่ละมุมวางหางไว้คนละตำแหน่ง การเอามุมข้างมาบอกความลึกแล้วมุมหน้าบอก
ความกว้าง ทำให้ได้หางที่ไม่ตรงกับภาพไหนเลย **ใช้มุมเดียวเป็นแหล่งอ้างอิง
จึงได้หางที่ตรงกับภาพนั้นจริง ๆ**

ภาพด้านหลังคือมุมที่เห็นหางชัดที่สุด แต่มีกับดัก: หางห้อย *ทับ* กางเกงอยู่
มันจึงอยู่ข้างในรูปร่าง ไม่ใช่ที่ขอบ — **mask มองไม่เห็นหางเลย ต้องแยกด้วยสี**

```
แบ่งสีช่วงล่างเป็น 2 กลุ่มด้วย k-means
  -> ลากท่อนเดียวกันลงไปตามความต่อเนื่อง
  -> เลือกกลุ่มที่ได้เส้น "ยาวและแคบ" (เสื้อผ้าจะกว้างแต่สั้น)
  -> ได้ (แถว, ตำแหน่ง X, ความกว้าง) ครบทุกแถว
```

ไม่ได้ฮาร์ดโค้ดสีกางเกงไว้ — hue ถูกแปลงเป็นเวกเตอร์บนวงกลม `(cos, sin)`
ก่อนเข้า k-means เพราะ hue วนรอบ สีแดงที่ค่า 179 กับ 1 อยู่ติดกันจริง
แต่ตัวเลขห่างกันสุดขอบ

**สองกับดักที่ทำให้แขน ขา และหางหายไปทั้งหมด**

เริ่มมองหาหางสูงเกินไปจะไปเจอ *เข็มขัด* ก่อน ซึ่งเป็นแถบกว้างพาดทั้งตัวและสี
ไม่ใช่เสื้อผ้า ตัวติดตามจะออกตัวบนเข็มขัดแล้วไหลไปตามขอบกางเกงแทนที่จะตามหาง
ได้หางที่วิ่งผิดทางและขาดเป็นท่อน `tail_band_top` จึงต้องเริ่มใต้เข็มขัด

และตอนตัดเนื้อหางออกจากลำตัว เคยใช้กฎว่า "ท่อนที่ไม่ใช่ลำตัว/ขา คือหาง"
ซึ่งใช้ได้ตอนที่ช่วงหางอยู่ต่ำกว่าระดับมือ พอเปลี่ยนมาลากจากภาพหลัง ช่วงหาง
ขยายขึ้นไปคลุมระดับมือด้วย **แขนกับมือจึงถูกทิ้งทั้งหมด เหลือแต่ตอ**
ตอนนี้ตัดเฉพาะท่อนที่ทับตำแหน่งหางจริงตามที่ลากไว้ ท่อนที่อยู่ไกลออกไปไม่ถูกแตะ

**ความลึกมาจากไหน** ภาพด้านหลังบอกแกน X กับความกว้างครบ แต่บอกความลึกไม่ได้เลย
เราจึงวางหางไว้ที่ *ผิวด้านหลังของลำตัว* ในแต่ละแถว ซึ่งเป็นที่ที่หางพาดอยู่จริง
และสมมติว่าหน้าตัดกลม เพราะหางสัตว์หนาพอ ๆ กันทุกทิศ การเดาว่ากลมสมเหตุผลกว่า
การไปเอาความลึกจากมุมอื่นที่วางหางคนละที่

```powershell
--crest-width 0          # ไม่คืนหนามสันหลัง
--tail-bones 0           # ไม่ใส่กระดูกหาง
--no-tail                # ไม่สร้างหางเลย
```

ปรับเพิ่มใน `config.py` — `tail_z_bias` ดันหางออกจากตัว (0 = ครึ่งหนึ่งจมอยู่ใน,
1 = พ้นตัวพอดี), `tail_band_top` จุดเริ่มมองหาหาง, `tail_trace_min_score`
ความเข้มงวดก่อนจะเชื่อว่าเจอหางจริง ถ้าแยกไม่ได้มันจะข้ามการสร้างหางไปเลย
แทนที่จะเดามั่ว

## การแยกขาออกจากหางใน silhouette

หางมักเชื่อมติดกับขาเป็น *ท่อนเดียวกัน* ใน silhouette ด้านหน้า การกรองทั้งท่อน
จึงทำอะไรไม่ได้ ต้องเล็มท่อนให้เหลือเฉพาะความกว้างของขา

`_limb_runs()` ไล่ติดตามขาจากเท้าขึ้นมาทีละแถว แล้วใช้ **ความสมมาตรของขาใน
แถวเดียวกัน** เป็นไม้บรรทัด — ขาที่ไม่ชนหางบอกได้ว่าขาที่ความสูงนั้นควรหนาเท่าไร
ส่วนเกินของอีกข้างคือหาง

สามกับดักที่ทำให้โมเดลพังระหว่างทาง และเช็คไว้แล้วในโค้ด

| กับดัก | อาการ |
|---|---|
| เริ่มจากแถวล่างสุด | เท้าสองข้างแตะพื้นคนละระดับ แถวล่างสุดมีเท้าเดียว ติดตามได้ขาเดียวทั้งตัว |
| หยิบ "สองท่อนที่กว้างที่สุด" เป็นเท้าคู่ | ได้นิ้วเท้าสองนิ้วของเท้าเดียวกัน แกนกลางลำตัวเพี้ยนไปไกล |
| จำความกว้างขาข้ามแถวแล้วเอามาตัด | ต้นขากว้างกว่าข้อเท้ามาก กลายเป็นลูปป้อนกลับที่ตัดแคบลงเรื่อย ๆ จนกินขาหาย |

แถวเริ่มต้นจึงต้องเป็นแถวที่เห็นสองท่อนกว้างใกล้เคียงกัน **และอยู่คนละฝั่ง**
ของแกนกลางลำตัว ส่วนแกนกลางเองใช้ค่า median จากหลายแถวเพื่อกรองแถวที่หยิบผิด

ไม่ต้องการหางเลยให้ใช้ `--no-tail` ปรับความไวที่ `--tail-min-rows`
และเกณฑ์เล็มขาที่ `leg_clip_factor` ใน `config.py`

## เรื่องหน้าตัดแนวนอน (`--carve-mode`)

ภาพ 3 มุมที่ 0°/90°/180° ให้ข้อมูลแค่ **สองแกน** จริง ๆ — front กับ back บอกแกน X
ซ้ำกัน ส่วน side บอกแกน Z เพียงมุมเดียว visual hull ตามนิยามจึงให้หน้าตัด
แนวนอนเป็น **สี่เหลี่ยม** (ช่วง X × ช่วง Z) ผลคือได้ก้อนเหลี่ยมเป็นชั้น ๆ
ไม่ใช่ร่างกาย

ค่าเริ่มต้น `--carve-mode ellipse` จึงปั้นหน้าตัดเป็นวงรีแทน โดยแยกชิ้นส่วน
ตามแกน X ในแต่ละแถว (ลำตัว / แขนซ้าย / แขนขวา / ขา) แล้วให้แต่ละชิ้นมีความลึก
ตามสัดส่วนความกว้างของตัวเอง แขนที่แคบจึงได้หน้าตัดเกือบกลม

การหาความลึกของลำตัวใช้วิธี **ไต่จากหัวลงมาหาเท้า** ไม่ใช่เลือกก้อนที่ใหญ่ที่สุด
เพราะส่วนที่ยื่นออกมาอย่างหางกวาดตัวในแนวนอน บางระดับความสูงมันกว้างกว่าลำตัว
ถ้าเลือกด้วยขนาดจะได้ตำแหน่งหางมาแทนขา แล้ววางขาผิดที่จนหลุดจากตัว

## ข้อจำกัดที่ต้องรู้ก่อนใช้

**ท่าทางต้องตรงกันทุกมุม** — นี่คือข้อกำหนดที่เข้มที่สุด ภาพ AI-generated
มักสร้างแต่ละมุมแยกกัน ทำให้ท่าทางเพี้ยนระหว่างมุข visual hull ตัดเฉพาะส่วนที่
อยู่ใน silhouette ของ *ทุก* มุม อะไรที่ไม่ตรงกันจะถูกลบทิ้ง ตัวตรวจ
`check_consistency` จะเตือนให้เมื่อเจอ แต่แก้ให้ไม่ได้ — ต้องไปแก้ที่ภาพต้นทาง

**ส่วนที่ยื่นออกมาต้องอยู่ตำแหน่งเดียวกันทุกมุม** — หาง ปีก ผมยาว อาวุธ
ถ้าขยับระหว่างภาพจะหายไปเกือบหมด

**หน้าตัดจะออกเหลี่ยมโดยธรรมชาติ** — visual hull จาก 3 มุมตั้งฉากให้หน้าตัด
เป็นสี่เหลี่ยม เราชดเชยด้วย `--hull-blur` และ Taubin smoothing แต่ส่วนเว้าลึก
ที่ไม่มีมุมไหนมองเห็น (ซอกใต้คาง ร่องกลางหลัง) จะตื้นกว่าจริงเสมอ

**ท่าต้องเป็น A-pose หรือ T-pose** — ตัวประเมินข้อต่อใน `landmarks.py` อ่าน
ตำแหน่งจากเรขาคณิต ไม่ได้ใช้โมเดลตรวจจับท่า ถ้าแขนทับลำตัวหรือท่าเคลื่อนไหว
มันจะวางข้อต่อผิด

**จุดที่ silhouette แยก ไม่ใช่ระดับข้อสะโพก** — ตัวละครที่ใส่กางเกงหลวมหรือ
ต้นขาชิดกัน ภาพจะเห็นเป็นก้อนเดียวต่อลงมาอีกไกลกว่าจะเห็นช่องว่างระหว่างขา
pipeline จะรับค่าที่วัดได้เฉพาะเมื่ออยู่ในช่วง 38–58% ของความสูง นอกช่วงนั้น
จะหันไปใช้ตำแหน่งที่สะโพกผายกว้างที่สุดแทน พร้อมเตือนให้ทราบ

**ตัวละครที่ไม่มีรอยคอดที่คอ** — คอสัตว์เลื้อยคลาน คอหนา เกราะคอ หรือหัวที่
แคบกว่าคอ ทำให้หาคอด้วยจุดที่แคบที่สุดไม่ได้ เมื่อเจอกรณีนี้ pipeline จะหันไป
ใช้สัญญาณที่สอง: **จุดที่แกนความลึกเลื่อนไปข้างหน้าเร็วที่สุด** เพราะหัวของสัตว์
ที่มีปากยื่นอยู่ค่อนไปด้านหน้าของลำตัวเสมอ แกนกลางความลึกจึงกระโดดตรงรอยต่อคอ
แม้ silhouette ด้านหน้าจะเรียบสนิทก็ตาม และจะบอกในคำเตือนว่าใช้สัญญาณไหน

**ไหล่ผูกกับคอ** — รอบแรกหาไหล่จากจุดที่ลำตัวผายกว้างสุด ซึ่งมักไปเจออกหรือ
ปีกหลังที่ต่ำกว่าข้อไหล่จริง พอได้ตำแหน่งคอที่เชื่อถือได้แล้วจะค้นไหล่ใหม่
เฉพาะในช่วง 2–16% ใต้คอลงมา

**โครงกระดูกเป็นมนุษย์ + หาง** — `BONE_PARENTS` ใช้ชุดกระดูกแบบ Mixamo และ
ต่อโซ่ `Tail1..TailN` + `TailEnd` เข้ากับ `Hips` ให้อัตโนมัติเมื่อตรวจเจอหาง
ปีก เขา หรือขาแบบสัตว์ยังไม่มีกระดูกรองรับ

**คุณภาพ skinning** — `--rig blender` ใช้ automatic weights ของ Blender ซึ่งพอ
สำหรับทดลอง ถ้าต้องการระดับ production ให้ใช้ `--rig none` แล้วเอา `.glb`
ไป auto-rig ที่ [Mixamo](https://www.mixamo.com) ซึ่งให้ weight ดีกว่าและแถม
คลังอนิเมชันมาด้วย

## โมเดลฐาน (กำลังพัฒนา)

visual hull สร้างรูปทรงจากศูนย์ มันจึงได้แต่ "ก้อนที่เงาถูก" และพังเสมอตรงจุด
ที่เงาบอกไม่ได้ ไม่ว่าจะเพิ่มความละเอียดแค่ไหน แนวทางโมเดลฐานพลิกโจทย์:
เอาโมเดลที่ *ถูกต้องอยู่แล้ว* มาดัดให้ตรงกับเงา นิ้วมือห้านิ้วกับคอจึงมีมา
ตั้งแต่ต้น ไม่ต้องเดาจากเงาซึ่งมองไม่เห็นมันอยู่แล้ว

วางไฟล์โมเดลฐาน (`.glb/.gltf/.obj/.ply` หรือ `.fbx` ซึ่งจะให้ Blender แปลงให้)
ไว้ใน `input/` แล้ว pipeline จะหยิบไปใช้เอง ปิดด้วย `--no-base-mesh`

### ที่ทำได้แล้ว

- **อ่านไฟล์แล้วจัดแกนเอง** — เดาแกนซ้าย-ขวาจาก *ความสมมาตร* ของการกระจาย
  vertex (ร่างกายคนเป็นภาพกระจกรอบระนาบกลางตัว) แล้วแยกแกนขึ้นกับแกนหน้า
  ด้วยความยาว เคยใช้ "แกนที่ยาวที่สุดคือแกนขึ้น" ซึ่งพังกับ T-pose เพราะ
  ช่วงแขนยาวพอ ๆ กับความสูง (วัดจากไฟล์จริงได้ 19.94 กับ 17.71) โมเดลเลย
  ถูกวางนอนตะแคง
- **หาข้อต่อของโมเดลฐานด้วยตัวประเมินตัวเดียวกับที่ใช้กับ hull** โดย
  voxelize มันแล้วเรียก `landmarks.estimate` — ได้ข้อต่อ *ชื่อเดียวกัน*
  ทั้งสองฝั่งโดยอัตโนมัติ ซึ่งตัดงานจับคู่จุดอ้างอิงที่เป็นส่วนยากที่สุด
  ของงาน fit โมเดลออกไปทั้งหมด
- **ดัดด้วย thin-plate spline** ที่ลากข้อต่อของฐานไปทับข้อต่อของตัวละคร
  (เคยลอง linear blend skinning ก่อน แล้วผิวฉีกเป็นรอยแตกและอกแยกเป็นสอง
  ก้อน เพราะ vertex ที่เลือกกระดูกคนละชุดกระโดดไปคนละทิศ TPS ให้สนามการ
  เปลี่ยนรูปผืนเดียวที่เรียบทั้งก้อน จึงไม่มีทางฉีกโดยนิยาม)

### ขั้นหมุนท่า (ทำแล้ว)

`src/blender_pose.py` สร้าง armature ที่ข้อต่อของโมเดลฐาน bind แล้วหมุนกระดูก
ทีละท่อนจากโคนไปปลายให้ทิศตรงกับโครงของตัวละคร แล้ว apply ลง vertex

เจอกับดักสองอันระหว่างทาง ซึ่งทั้งคู่ล้มแบบ *เงียบ*:

- **bone heat weighting ล้มโดยไม่มี error** — operator คืนค่าสำเร็จ สร้าง
  vertex group ครบ 23 กลุ่ม แต่ไม่ใส่น้ำหนักให้ vertex สักจุด (วัดได้
  0/21692) การ pose จึงไม่ขยับอะไรเลยโดยไม่มีอะไรบอก ตอนนี้ `bind_checked`
  *วัดผลลัพธ์* แล้วถอยไป envelope หรือน้ำหนักตามระยะที่คำนวณเองถ้าไม่ได้ของ
- **face index เกินช่วงจนทั้ง process segfault** — การส่งผ่าน Blender ทำให้
  topology เปลี่ยน (21692 -> 18852 หลังรวม vertex ที่ exporter แตกไว้) แต่
  ผู้เรียกยังใช้ faces ชุดเดิม open3d ที่รับไปต่อจึง segfault (exit 139)
  ไม่ใช่ exception ที่จับได้ แก้ด้วยการให้ `fit_skeleton` คืน faces มาด้วย

### ขั้นอัดปริมาตร (ทำแล้ว)

TPS ลากเฉพาะ *ข้อต่อ* ไปตรงกัน ความหนาจึงยังเป็นของโมเดลฐานล้วน ๆ ตัวละคร
ที่ล่ำกว่าเลยออกมาผอมเก้งก้าง (หนา 0.37 m ขณะที่เงาบอก 0.68 m)

`fit_volume` วัดจากแกนกระดูกออกไปว่าเงาทึบถึงระยะไหน แล้วย้าย vertex ไป
ตามสัดส่วนนั้น รูปหน้าตัดเดิม (ร่องกล้ามเนื้อ) จึงถูกเก็บไว้ ต่างจาก
shrink-wrap ที่ดูดผิวไปแปะ hull จนรายละเอียดหายหมด

ต้อง **เกลี่ยเวกเตอร์การขยับ** ไปตามผิวก่อนใช้ ไม่ใช่แค่เกลี่ยตัวคูณ เพราะ
vertex ที่อยู่ติดกันแต่ถูกจับให้อยู่คนละกระดูกมีแกนอ้างอิงคนละชุด ต่อให้
คูณเท่ากันก็ถูกดันคนละทาง ผิวแตกเป็นแผ่น ๆ (ลองแบบเกลี่ยตัวคูณอย่างเดียว
แล้วยังแตกอยู่)

### สองจุดที่ทำให้ผลพลิกจาก "ใช้ไม่ได้" เป็น "ใช้ได้"

**1. อย่าประเมินข้อต่อใหม่จาก mesh ที่ posed แล้ว** เดิมเอา mesh ที่หมุนแล้ว
ไป voxelize แล้วเรียกตัวประเมินข้อต่อซ้ำ ซึ่งให้คำตอบไม่ตรงกับที่ armature
วางไว้จริง รายงานว่า "เหลือต่างจากเป้า 60 องศา" ทั้งที่หมุนไปครบแล้ว —
ความคลาดนั้นเป็นของการ *วัด* ไม่ใช่ของการหมุน แล้ว TPS ก็ไปดัดแก้สิ่งที่
ไม่ได้ผิด ตอนนี้สคริปต์ฝั่ง Blender เขียนตำแหน่งข้อต่อหลังหมุนออกมาให้ตรง ๆ

**2. ต้องยืด/หดกระดูกด้วย ไม่ใช่หมุนอย่างเดียว** ถ้าหมุนอย่างเดียว ความยาว
ยังเป็นของโมเดลฐาน ข้อต่อปลายสายจึงไปไม่ถึงเป้าและความคลาดสะสมลงไปทั้งโซ่

ผลรวมของสองข้อ: ช่วงแขนหลังหมุนแคบลงจาก 1.62 m เหลือ 1.31 m มุมที่เหลือ
ต่างจากเป้าลดจาก 60 องศาเหลือ 42 (และท่อนที่เหลือคือ `Hips->LeftUpLeg`
ซึ่งเป็นครึ่งความกว้างเชิงกราน ไม่ใช่ท่าทางจริง) ความหนาตัวจาก 0.43 m
เป็น 0.56 m เทียบกับที่เงาบอก 0.68 m

### ต่อหาง (ทำแล้ว)

โมเดลฐานเป็นคน จึงไม่มีหางมาให้ ต่างจากเส้นทาง hull ที่หางโผล่มาเองเพราะ
ปั้นทุกอย่างจาก occupancy ก้อนเดียวกัน

`build_tail_mesh` ปั้นหางเป็น *ท่อ mesh* จากแกนกลางที่ `tailtrace` ลากไว้
พร้อมรัศมีที่ `_add_tail_tube` เก็บมาให้ (เพิ่ม `HullGrid.tail_radius`)
ใช้ parallel transport หมุนกรอบอ้างอิงตามแกน ไม่งั้นท่อจะบิดตัวเองตรงช่วง
ที่หางหักเลี้ยว ได้ topology เป็นวงแหวนเรียงตามแกน ซึ่ง rig แล้วงอสวยกว่า
ผล marching cubes มาก

สองอย่างที่ต้องระวังตรงรอยต่อ:

- **ต้องลากโคนหางเข้าไปฝังในสะโพก** ขั้นปั้นหางใน hull ดันหางออกหลังตาม
  `tail_z_bias` ซึ่งถูกตอนที่ทุกอย่างเป็น occupancy ก้อนเดียวแล้วเบลอรวมกัน
  แต่พอหางเป็น mesh แยกชิ้น โคนที่ลอยหลังตัว 30 voxel จะโผล่ให้เห็น
- **ไม่ปิดฝาที่โคน** โคนกว้าง 50 voxel ถ้าปิดเป็นจานแบนจะเห็นเป็นแผ่นลอย

### หัว: TPS เฉพาะส่วน

การขยายตามรัศมี (`fit_volume`) ทำหัวไม่ได้ มันเก่งกับสิ่งที่หนาขึ้น *ทั้งรอบ*
(แขน ขา ลำตัว) แต่ปากยื่นไป *ทางเดียว* ไกลกว่ารัศมีกะโหลกสามเท่า พอต้อง
เกลี่ยเวกเตอร์การขยับเพื่อกันผิวแตก ท้ายทอยที่ไม่ต้องขยับก็ถูกเฉลี่ยเข้ามา
จนตัวคูณที่หน้าเหลือราว 1.2 — ปากเลยไม่เคยโผล่

`fit_head` ใช้ TPS แทน ซึ่งเรียบ *โดยนิยาม* จึงไม่ต้องเกลี่ยทับทีหลัง และ
เก็บการยื่นเฉพาะจุดไว้ได้ จุดควบคุมมาจากการยิงรังสีจากกลางหัวออกไปทุกทิศ
แล้วดูว่าเงาทึบถึงไหน

สี่อย่างที่ต้องทำ ไม่งั้นมันพังคนละแบบกัน:

| อาการ | สาเหตุ | ทางแก้ |
|---|---|---|
| vertex กระเด็น 521 voxel ตัวกว้าง 1.8 m | หว่านจุดตรึงทั่วลำตัว TPS ต้องสนองข้อบังคับที่ขัดกันในระยะใกล้ | ตรึงเฉพาะ *วงแหวนรอบคอ* |
| หัวแตกเป็นเศษแหลม | จุดที่ขยับ 30 voxel อยู่ติดกับจุดที่ห้ามขยับ | เว้นจุดควบคุมให้อยู่เหนือคอ 30% ของความสูงหัว |
| งอกเงี่ยงยาวหลายอัน | รังสีไม่กี่เส้นยิงโดน *หนามสันหลัง* บนกะโหลกใน hull | กรองระยะด้วย median ของ 17 ทิศที่ใกล้กัน |
| ผิวหักเป็นมุม | เพดานกันพุ่งตัดคนละระดับระหว่าง vertex ข้างกัน | ตั้งเพดานหลวม ๆ ไว้เป็นตาข่ายรองเท่านั้น + ไล่ระดับให้จางหายที่คอ |

median สำคัญกว่าค่าเฉลี่ย เพราะมันตัดค่าโดดทิ้งได้โดยไม่กลืนรูปทรงจริง —
และปากที่ยื่นออกมากินหลายสิบทิศติดกัน จึงรอดจากการกรอง

**ผลที่ได้:** การขยับสูงสุดลดจาก 521 เหลือ 24 voxel หัวกลายเป็นกะโหลก
สัตว์เลื้อยคลานที่กว้างและแบนแทนหัวคน

**ที่ยังไม่ได้:** ยังไม่ใช่ปากจระเข้ที่คม ข้อจำกัดตอนนี้เป็นเรื่อง
*topology* ไม่ใช่อัลกอริทึม — หน้าคนของโมเดลฐานไม่มีความหนาแน่นของ vertex
ที่เรียงไปตามแนวขากรรไกรยาว ๆ การดึงมันออกไปจึงได้ปากแบนไม่ใช่ปากคม
ถ้าต้องการปากจริง ต้องใช้โมเดลฐานที่หัวเป็นสัตว์อยู่แล้ว หรือปั้นหัวแยก
ชิ้นแบบเดียวกับหาง

### สถานะตอนนี้

เส้นทางนี้ให้ **มือที่มีห้านิ้วจริง เท้าที่มีนิ้วจริง และหางที่ rig ได้สวย**
รันครบ pipeline รวม rig + อนิเมชันได้ใน 63 วินาที

แต่ยัง `use_base_mesh = False` ไว้ก่อน (เปิดด้วย `--base-mesh`) เพราะสำหรับ
ตัวละครตัวนี้โดยรวมยังสู้ hull ไม่ได้ — โมเดลฐานเป็น *คน* จึงไม่มีหาง
ไม่มีปากจระเข้ และไม่มีเล็บ ส่วนลำตัวที่ถูกอัดให้ชนเงาก็ออกมาเป็นพุง
เพราะกล้ามท้องของโมเดลฐานถูกขยายตามไปด้วย

ทางไปต่อ เรียงตามผลตอบแทน:

1. **ต่อหาง ปาก และเล็บจากกลไกเดิม** (`tailtrace`, แนวคาง, ผังฝ่าเท้า)
   เข้ากับร่างที่ได้จากโมเดลฐาน — เส้นทางนี้จะชนะ hull ทันทีที่ทำได้
2. **ใช้โมเดลฐานท่า A-pose** จะได้ไม่ต้องหมุน 98 องศา ยิ่งหมุนมากยิ่งพึ่ง
   คุณภาพ weight ซึ่งตอนนี้ตกไปใช้ envelope เพราะ bone heat ล้ม
3. แยกสเกลแกน X กับ Z ตอนอัดปริมาตร ลำตัวจะได้กว้างแบนแทนที่จะกลมเป็นพุง

## หัวกับคอ

หัวพังเป็นอาการคลาสสิกของ visual hull ที่มีแต่มุมตั้งฉาก และต้นเหตุคือ
**ความลึกของแถวหนึ่งถูกเอาไปครอบทั้งแถว** ปากสัตว์ยื่นไปข้างหน้า 15 ซม.
mask ด้านข้างที่แถวนั้นจึงกินตั้งแต่ท้ายทอยถึงปลายปาก พอเอาความลึกนั้นไป
ทำหน้าตัดเต็มความกว้างของบ่า จะได้แผ่นแบนคาดรอบคอเหมือนปีกหมวก

วิธีเดิมคือ "หั่นความลึกของแถวที่กว้าง แล้วเอาส่วนที่หั่นมาแปะคืนเป็นก้อนปาก"
โดยไล่ระดับการหั่นตามความกว้างของแถว ซึ่งพังเพราะความกว้างของหัวค่อย ๆ
เพิ่มขึ้นจนข้ามเกณฑ์ตรงกลางหัวพอดี กลางหัวจึงโดนหั่นเป็นหย่อม ๆ เกิด
**จานแบนคาดกลางหัวกับก้อนเห็ดบนกะโหลก**

ตอนนี้แบ่งตัวด้วย **แนวคาง** ที่อ่านจากมุมข้างแทน: ไล่จากยอดหัวลงมา ขอบหน้า
ของ silhouette จะยื่นออกไปตามแนวปากจนสุดที่ปลายปาก แล้ว *ถอยกลับฮวบเดียว*
ตรงใต้คาง เพราะใต้คางคืออก (วัดได้ว่าถอย 12 ซม. ภายในแถวเดียว) จากนั้น

- **เหนือคาง** ไม่หั่นเลย หัวสัตว์ปากยาวลึกกว่ากว้างสองเท่าเป็นเรื่องปกติ
  ปล่อยให้เป็นไปตามที่มุมข้างบอก (ตรวจแล้วว่าโปรไฟล์หัวทับ mask เกือบสนิท)
- **ใต้คางลงมา** หั่นด้วย `--body-aspect` จากด้านหลัง ซึ่งเป็นตัวที่กันปีกหมวก
  และกันหางที่เชื่อมติดขาในมุมข้างไปด้วยในคราวเดียว

ต้องหาแนวคางจากโปรไฟล์ **ดิบ** ก่อนเกลา: พอเกลาด้วย gaussian 4 แถว การถอย
32 voxel จะกลายเป็นความชัน 3 voxel ต่อแถว ซึ่งจมอยู่ในสัญญาณรบกวนจนหาไม่เจอ

`--max-aspect` ยังมีอยู่ (ค่าเริ่มต้น 0 = ปิด) ไว้เปิดกับตัวละครที่คอเล็กกว่า
หัวมากจนยังเกิดปีกหมวกแม้จะแบ่งด้วยแนวคางแล้ว

### คอ: รายละเอียดบนผิว ไม่ใช่เรื่องของเส้นขอบ

ตัวละครที่ไหล่ใหญ่ชนกราม **ไม่มีคอให้เห็นในมุมไหนเลย** — วัดความกว้างมุมหน้า
ทีละ 1% ของความสูงแล้วโตขึ้นทางเดียวตลอดจากยอดหัวถึงบ่า ไม่มีรอยคอดให้จับ
ส่วนมุมข้างก็เห็นแต่ขอบนอกของบ่า คอถูกบังอยู่ *ข้างใน* ทั้งสองมุม
hull จึงเติมเนื้อเต็มช่องระหว่างคอกับยอดบ่า ได้หัวกลืนเป็นทรงกรวยเหมือนใส่ฮู้ด

กุญแจคือคอไม่ได้อยู่ที่เส้นขอบ แต่อยู่ที่ผิว:

| แกน | เส้นขอบของแถวนั้นมาจาก | คออยู่ตรงไหน |
|---|---|---|
| X (มุมหน้า) | ปลายบ่าทั้งสองข้าง | ตรงกลาง ไม่เกี่ยวกับขอบ |
| Z (มุมข้าง) | คอ/อก ซึ่งลึกสุดอยู่แล้ว | เก็บไว้เต็ม ไม่แตะ |

การ **ลดความลึกเฉพาะช่วงที่อยู่ข้าง ๆ คอ** จึงไม่ไปแตะเงาของมุมไหนเลย
แต่ทำให้ซอกระหว่างคอกับบ่าโผล่ออกมา ซึ่งเป็นสิ่งที่ตาคนใช้อ่านว่า
"หัวตั้งอยู่บนคอ" รูปทรงที่ได้คือแกนกลางเป็นลำคอความลึกเต็ม สองข้างเป็น
สันบ่าที่บางตรงใต้คางแล้วหนาขึ้นจนเต็มเมื่อลงไปถึงระดับไหล่ ตรงกับกล้ามเนื้อ
สะบักที่ลาดลงจากคอไปหาหัวไหล่

ขั้นนี้ **ตัดอย่างเดียว ไม่เพิ่มเนื้อ** จึงไม่มีทางทำให้เกินภาพต้นทางได้
(ตรวจแล้ว: หลังเซาะคอ เงามุมหน้าเกินภาพ 1 px เงามุมข้างเกิน 93 px ซึ่งเป็น
ส่วนใต้คางที่เกินอยู่ก่อนแล้ว)

ปรับด้วย `--neck-width` (ความกว้างลำคอ) กับ `--neck-shoulder`
(สันบ่าบางแค่ไหน — ต่ำ = คอเด่นขึ้น) หรือปิดด้วย `--no-neck`

ถึงอย่างนั้น นี่เป็นการ *เดาตามกายวิภาค* ไม่ใช่ข้อมูลจากภาพ ถ้าอยากได้คอ
ที่ตรงกับตัวละครจริง ๆ ต้องมีภาพที่เห็นคอ: เงยหน้าขึ้นเล็กน้อย หรือหันหัว
ไปด้านข้างสัก 20-30 องศา ให้เห็นช่องว่างระหว่างกรามกับบ่า

## ข้อต่อแขน: อ่านจากแกนแขนในภาพ ไม่ใช่จากจุดที่ยื่นออกข้างสุด

วิธีเดิมหาปลายมือจาก "จุดที่ยื่นออกด้านข้างสุดในช่วงที่แขนกวาดถึง" แล้ววาง
ข้อมือที่ 92% ของเส้นตรงไหล่→จุดนั้น และข้อศอกที่กึ่งกลาง

วิธีนี้สมมติว่าแขนเหยียดเฉียงออกแบบ A-pose กว้าง ๆ แต่ตัวละครที่ *ปล่อยแขนลง
แนบตัว* จุดที่ยื่นออกข้างสุดคือ **กล้ามท่อนแขน ไม่ใช่มือ** ข้อมือจึงถูกวางสูง
เกินจริงและข้อศอกไปตกกลางต้นแขน กระดูกแขนลอยออกนอกตัวละครไปเลย
(ตัวประเมินเองก็เตือนว่า "ช่วงแขนแคบกว่าไหล่มาก ตำแหน่งข้อศอก/ข้อมือคลาดเคลื่อน")

ตอนนี้ `trace_arms` ไล่ตามท่อนแขนใน silhouette ด้านหน้าทีละแถว (ใช้ตัวติดตาม
ตัวเดียวกับที่หาเขตมือ) ได้ **แกนกลางจริงของแขนมาทั้งเส้น** แล้ววางข้อต่อ
บนแกนนั้นด้วยสัดส่วนตามความยาวแกน นับจากรักแร้ลงไป — ข้อศอกที่ `elbow_frac`
(0.32) ข้อมือที่ `wrist_frac` (0.70) ข้อต่อจึงอยู่บนตัวแขนไม่ว่าแขนจะเหยียด
หรือแนบตัว

ข้อควรรู้: `hand_length_frac` เป็นคนละเรื่อง มันคือความกว้างของ *เขตกันเบลอ*
ของมือ ซึ่งตั้งเผื่อไว้กว้าง เอามาใช้เป็นตำแหน่งข้อมือไม่ได้ (ลองแล้วได้
ข้อศอกกับข้อมือห่างกัน 4 ซม. ขณะที่ต้นแขนยาว 28 ซม.)

## มือกับเท้า

มือกับเท้าเป็นจุดที่ visual hull พังเป็นปกติ ไม่ใช่เพราะสุ่มหยาบ แต่เพราะ
*ไม่มีข้อมูล* และเพราะทุกขั้นตอนที่ทำให้ลำตัวดูดีล้วนทำลายนิ้วทิ้งหมด

| ขั้นตอน | ตั้งใจทำอะไร | ทำอะไรกับนิ้ว |
|---|---|---|
| `spike_open` | ลบหนามสันหลังที่กลายเป็นสันวงแหวน | ลบนิ้วทุกนิ้ว (นิ้วหนาราว 4 voxel) |
| `silhouette_smooth` | เกลาขอบที่สั่น 1-2 px | ถมร่องระหว่างนิ้ว |
| `depth_falloff` | ให้แขนที่แคบมีหน้าตัดเกือบกลม | ให้นิ้วลึกเท่าสะโพก → เป็นครีบแบน |
| `hull_blur` | ลบเหลี่ยมก่อน marching cubes | ละลายอะไรที่บางกว่า ~5 voxel |

ทางแก้ไม่ใช่การปิดขั้นตอนพวกนี้ (ลำตัวจะกลับไปเป็นขั้นบันได) แต่คือ
**จำกัดขอบเขต**: `src/extremities.py` หาว่ามือกับเท้าอยู่แถวไหน แล้วใช้กฎ
คนละชุดเฉพาะในเขตนั้น — คืน silhouette ดิบ เบลอด้วย sigma ที่เล็กกว่า
และให้นิ้วมีหน้าตัด *กลม* แทนที่จะลึกตามลำตัว

เรื่องที่เป็นข้อจำกัดจริง ๆ สองข้อ:

**ความหนาของมือ ไม่มีมุมไหนวัดได้เลย** มุมหน้าเห็นหลังมือ มุมข้างเห็นมือ
ซ้อนอยู่กับสะโพกจนแยกไม่ออก กฎเดิมจึงไปหยิบความลึกของสะโพกมาใช้ มือเลย
หนา 14 ซม. เป็นก้อนนวม ตอนนี้ใช้สัดส่วนของมือเอง (`--palm-round`, ค่าเริ่มต้น
0.45 เท่าของความกว้างมือ) ซึ่งจริงกับมือแทบทุกแบบ

**นิ้วเท้าอยู่บนระนาบ X-Z ซึ่งไม่มีมุมไหนมองเห็น** มุมหน้าเห็นร่องระหว่าง
นิ้วแค่ 2 ซม. ล่างสุดของเท้า (สูงกว่านั้นนิ้วรวมเป็นหลังเท้าก้อนเดียวตาม
กายวิภาคจริง) เท้าจึงออกมาเป็นก้อนรองเท้าบูทเสมอ

ทางแก้คือใส่ **ภาพมองจากใต้ฝ่าเท้า** เพิ่มมาอีกใบ ตั้งชื่อว่า `down`,
`sole` หรือ `bottom` — `src/soleplan.py` จะดึงรูปฝ่าเท้าทั้งสองข้างออกมา
แล้วเอาไปเป็นหน้าตัดจริงของเท้าแทนวงรีที่เดาเอา นิ้วแยกชัดที่พื้นแล้วค่อย ๆ
กลืนเป็นหลังเท้าเมื่อสูงขึ้น (`sole_merge_*`)

ภาพใบนี้ **ไม่เข้า visual hull** เพราะมันเป็นภาพ perspective แรง (ฝ่าเท้า
ใหญ่เกินจริงเพราะอยู่ใกล้กล้อง) เราใช้มันเป็น *รูปร่างเชิงสัดส่วน* อย่างเดียว
แล้วไปยืดให้พอดีกับความกว้างเท้าจากมุมหน้าและความยาวเท้าจากมุมข้าง ซึ่ง
สองค่านั้นแม่นอยู่แล้ว สิ่งที่ภาพนี้ให้คือ "นิ้วอยู่ตรงไหนบนฝ่าเท้า" เท่านั้น
ซึ่งพอดีกับสิ่งเดียวที่ขาด

ถ้าภาพมุมล่างมีของพาดทับเท้าข้างหนึ่ง (เช่นหางทอดมาทับ) ตัวดึงจะเลือกใบที่
เล็กกว่าแล้วพลิกกระจกใส่อีกข้างให้เอง เพราะเท้าสองข้างเป็นภาพกระจกกันอยู่แล้ว
และของที่พาดทับมีแต่จะ *เพิ่ม* พื้นที่

## ภาพต้นทางที่ให้ผลดีที่สุด

- ท่า A-pose หรือ T-pose ยืนตรง แขนไม่ทับลำตัว
- ทุกมุมเป็นท่าเดียวกันเป๊ะ (สร้างพร้อมกันจาก prompt เดียว หรือใช้ ControlNet ล็อกท่า)
- พื้นหลังสีพื้นหรือโปร่งใส
- มองเห็นตัวละครเต็มตัว ตั้งแต่ยอดหัวถึงฝ่าเท้า ไม่มีส่วนใดถูกตัด
- กล้องมุมเดียวกัน ระยะเท่ากัน ไม่มี perspective แรง
- **กางแขนออกจากลำตัวให้เห็นช่องว่างใต้รักแร้ชัด ๆ** ตัวหาเขตมือใช้การที่แขน
  แยกออกจากลำตัวใน silhouette เป็นสัญญาณ ถ้าแขนแนบลำตัว มือจะหาไม่เจอ
  แล้วนิ้วจะถูกเกลาหายเหมือนเดิม
- **แยกนิ้วมือออกจากกัน** อย่ากำมือหรือให้นิ้วชิดกัน มุมหน้าเป็นมุมเดียวที่
  เห็นร่องระหว่างนิ้ว ถ้านิ้วชิดกันในภาพ ก็ไม่มีร่องให้ไปปั้นต่อ
- ถ้าอยากได้นิ้วเท้า ให้เพิ่มภาพมองจากใต้ฝ่าเท้า (`down.jpeg`) — ดูหัวข้อ
